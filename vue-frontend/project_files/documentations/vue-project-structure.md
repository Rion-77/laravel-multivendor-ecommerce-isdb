# Vue 3 Project Folder Structure

A scalable structure following official Vue conventions (`create-vue`, Vite, Vue Router, Pinia, TypeScript, Vitest).

## Quick Start

```bash
npm create vue@latest my-vue-app
cd my-vue-app
npm install
npm run dev
```

The scaffolder generates the core of this structure. Folders marked *(add manually)* are not generated by default.

## What Each Folder Is For

| Folder | Purpose |
|---|---|
| `public/` | Static files served as-is (favicon, robots.txt). Not processed by Vite. |
| `src/assets/` | Images, fonts, and global styles processed by the build. |
| `src/components/` | Reusable pieces. Split into `common`, `layout`, and `features` to stay findable as the app grows. |
| `src/composables/` | Reusable stateful logic written as `useXxx` functions. |
| `src/constants/` | App-wide constant values. |
| `src/directives/` | Custom Vue directives (e.g. `v-focus`). |
| `src/layouts/` | Wrapper components for groups of pages (e.g. with or without sidebar). |
| `src/plugins/` | Setup for third-party plugins (i18n, UI libraries). |
| `src/router/` | Route definitions and navigation guards (e.g. auth checks). |
| `src/services/` | API calls, so components never talk to `fetch`/`axios` directly. |
| `src/stores/` | Pinia stores for global state. |
| `src/types/` | Shared TypeScript types and declarations. |
| `src/utils/` | Pure helper functions with no Vue dependency. |
| `src/views/` | Components that routes point to, one per page. |
| `tests/` | Unit tests (Vitest) and end-to-end tests (Playwright/Cypress). |

## Naming Conventions

- **Components:** PascalCase, e.g. `BaseButton.vue`, `UserCard.vue`.
- **Views:** PascalCase with a `View` suffix, e.g. `HomeView.vue`, to tell them apart from reusable components.
- **Base components:** prefix with `Base` (or `App`) for generic UI, e.g. `BaseInput.vue`.
- **Composables:** camelCase starting with `use`, e.g. `useAuth.ts`.
- **Stores:** camelCase named after the domain, e.g. `auth.ts`, `user.ts`.
- **Directives:** camelCase starting with `v`, e.g. `vFocus.ts`.
- **Tests:** match the file under test with `.spec.ts`, e.g. `BaseButton.spec.ts`.

## Scaling Up

This is a **type-based** structure (all components together, all stores together). It works well for small to mid-size apps. When you find yourself jumping between many folders to change one feature, consider moving to a **feature-based** structure:

```
src/
├── app/                  # App bootstrap, router, global providers
├── features/
│   ├── auth/
│   │   ├── components/
│   │   ├── composables/
│   │   ├── services/
│   │   ├── stores/
│   │   ├── types.ts
│   │   ├── routes.ts
│   │   └── index.ts      # Public API of the feature
│   └── orders/
├── shared/               # Used by 2+ features
└── assets/
```

Keep each feature's `index.ts` as its public API, and avoid importing from another feature's internals.
